# Мой участок

Telegram-бот для контроля земельного участка после подачи заявления в администрацию. Он сохраняет карточку участка, напоминает о сроках по извещению и аукциону, а также хранит ссылки на официальные источники.

Это MVP, а не юридический сервис: бот не гарантирует предоставление участка и в каждом сценарии направляет пользователя к официальному источнику.

## Что реализовано

- `/start`, онбординг, «Как это работает» и дисклеймер;
- основной сценарий заявления на участок без кадастрового номера, плюс отдельный сценарий с номером;
- список и карточка участков, статусы и отключение контроля;
- ручное добавление извещения и аукциона;
- напоминания за 7, 3 и 1 день, в день дедлайна и через 2 дня после извещения;
- дедупликация напоминаний на уровне БД;
- SQLite для локальной разработки и PostgreSQL для production;
- Docker, Alembic, Ruff, mypy, pytest и GitHub Actions.

## Быстрый старт

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN`.
3. Установите зависимости и поднимите схему:

```bash
uv sync --all-groups
uv run alembic upgrade head
uv run my-land-bot
```

Для Docker:

```bash
docker compose up --build
```

## Команды разработки

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest
```

Те же действия доступны через `make install`, `make migrate`, `make run`, `make lint` и `make test`.

После изменения моделей создайте миграцию и проверьте её до коммита:

```bash
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
```

## Структура

```text
src/my_land_bot/
  handlers/       Telegram-сценарии и FSM
  services/       бизнес-логика и планировщик напоминаний
  models.py       SQLAlchemy-модели
  keyboards.py    inline-клавиатуры
  config.py       конфигурация окружения
tests/            unit-тесты бизнес-правил
```

## Следующие продуктовые шаги

Полуавтоматический поиск публикаций стоит добавлять отдельным источником данных с ручным подтверждением совпадения. Для production также нужны PostgreSQL, мониторинг ошибок и отдельный worker для напоминаний.
